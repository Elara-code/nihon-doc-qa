## 优化一：混合检索（Hybrid Search）

### 问题
纯向量检索在**缩写 / 专有编号**上不可靠：`ITU-T / ANSI / JNLA` 这类词，
向量会因周围语义相近而召回不到精确包含它们的段落。

### 方案
- 加 **BM25 关键词检索**（`rank_bm25`），与向量检索并行召回。
- 中日文没有空格分词、又不想引入 MeCab/jieba 的重依赖，自写 `src/tokenizer.py`：
  ASCII 型号整词保留（`itu-t`、`ansi`）+ CJK **bigram**，足够稳定。
- 两路结果用 **RRF（Reciprocal Rank Fusion）** 融合：
  `score = Σ 1/(k + rank)`。只看排名不看原始分，规避
  "向量距离"和"BM25 分"量纲不可比的问题。

### 效果（诚实）
- 最终命中率：vector 67% → hybrid **67%**（持平，未提升）。
- **不能讲"混合检索提升了命中率"**，数据不支持。
- 真正发生的事：bge-m3 多语言能力本就较强，缩写类问题向量已能召回，所以
  **最终命中率没差**；hybrid 的价值更多体现在**召回层**——把正确段捞进
  候选池，但是否能"排到前列"还是要看排序层。这正是引入 rerank 的契机。

## 优化二：重排序（Rerank）— 真正拉开差距的一步

### 问题
混合检索给出的 top-k 里，"最相关的段"未必排第一，尤其是含
**长缩写全称**或**深埋数值**的问题——它们的段落语义和提问相似度并不突出。

### 方案
**交叉编码器** `bge-reranker-v2-m3`：把 query 和每个候选拼起来联合编码打分，
比双塔向量"分别编码再算相似度"精确得多。代价是慢，所以只对融合后的
20 个候选精排，取 top_k。

### 效果（教科书级对比）
命中率：67% → **83%**（+16 个百分点）。两个干净的对比例子：

| 题 | vector | hybrid | rerank |
|---|---|---|---|
| Q10 「エコセメントの経済効果試算額（5920億）」 | ❌ | ❌ | ✅ |
| Q11 「ITU-T が指す略称」 | ❌ | ❌ | ✅ |

**为什么是 rerank 的功劳，不是 LLM 蒙的？**
hybrid 和 rerank 喂给 LLM 的**候选池是同一批**（都是 RRF 融合后的 top-20）。
hybrid 答不出，说明正确段落在候选池里但没进 top-5；rerank 用交叉编码器
把它捞到第一，LLM 才能答对。这就把 rerank 价值的归因切干净了。

## Day 15 沿途修了个真 bug：日文 PDF 段内伪换行

跑完测试后 Q7「改正工業標準化法の施行予定」三种模式**全 ❌**，但原文 p.4
明明有这句。深挖后发现：

- 现象：索引里**找不到** `改正工業標準化法` 这个子串。
- 定位：PyMuPDF 按视觉行提取，日文版式每 30 字左右就换行，
  原文 `改正/n工業標準化法` 被一个伪换行打断；
  全文统计 **1874 处** CJK 字符间的伪换行。
- 影响面：所有跨视觉行的长词都被切碎——`国際電気/n標準会議`（IEC 全称）、
  `国際電気通信連合/n…`（ITU-T 全称）等等，BM25 失配、向量语义稀释。
- 修复：`src/text_utils.py` 加一行正则——只清除 CJK 字符之间的**单个**换行，
  保留 `\n\n+` 的真段落分隔。验证：1874 → 0，段落结构未破坏。

> 这是面试时讲"我会做工程定位"的好故事：从一道题失败 → 怀疑切块/语料 →
> 写探针验证 → 用正则量化问题面 → 精准最小化修复 → 验证无副作用。

## Q7 深挖：修了 bug 还是失败，暴露的更深问题

修完伪换行 bug 后重跑，Q7 **仍然三种模式全 ❌**——比 bug 更深的问题在等着。

### 排查链路（逐层证伪）

1. **怀疑：chunk 里没答案？** → 检查 chunk #8 全文：包含 `2005年10月施行予定の改正工業標準化法...JNLA(試験所認定)`，**答案完整存在**。
2. **怀疑：BM25 找不到？** → 实测 chunk #8 在 BM25 排 **#1**，分数 75.07，远超 #2 的 40.90。
3. **那为什么 LLM 答"未找到"？** → 说明 chunk #8 没进送给 LLM 的 top-5。

### 真正的原因：「主题混杂 chunk」+ RRF 反向放大

chunk #8 是个 500 字的段：
- **前 400 字**：第2章 2-1 节背景介绍（WTO/TBT 协定、国际标准化重要性…）
- **末尾 70 字**：顺带提一句改正工業標準化法的施行时间——**答案就在这一句**

于是：
- **BM25**（关键词）→ 完美命中 → 排 #1 ✅
- **向量**（整段语义）→ 判定"这段在讲 WTO/TBT 背景" → 排名很低 ❌
- **RRF 融合** → 偏爱"两路都中等"的 chunk → chunk #8（一路 #1、一路靠后）反而打不过那些两路都排第 5-10 的 chunk → **被挤出 top-5**
- **rerank**（cross-encoder 也是看整段语义）→ 同样不偏好 chunk #8

这解释了**为什么 hybrid 反而比 vector 退步**（Q2 ANSI 也是同款）：RRF 在"一路压倒性、另一路无感"的场景下会反向损失。

### 给面试讲的关键洞察
> "RAG 不是把检索分数加起来就完事。答案分布在 chunk 内的什么位置、chunk 的整体语义是否和答案对齐，
> 决定了**哪种检索方式擅长，哪种融合策略会反向放大问题**。"

### 生产环境的修复路径（按代价排）

| 档位 | 方案 | 工作量 | 预期效果 |
|---|---|---|---|
| 🟢 立即 | 调大 top_k（5→10）+ score-gap aware 融合（BM25 #1 远超 #2 时强制保留） | 1 天 | 大概率解 Q7 |
| 🟢 立即 | 查询意图路由：事实型问题 BM25 权重拉高，概念型向量权重拉高 | 1 天 | 减少 RRF 反向放大 |
| 🟡 中期 | **Small-to-Big / Parent-Child 检索**：embed 小颗粒（句子）做精准匹配，返回大颗粒（段落）给 LLM | 3-5 天 | 根治"答案被周围无关文本稀释" |
| 🟡 中期 | 语义切块代替固定窗口：按章节/段落边界切，让 chunk 主题集中 | 3-5 天 | 减少 needle-in-haystack 类失败 |
| 🔴 最优 | **Contextual Retrieval**（Anthropic 2024）：每个 chunk embed 前用 LLM 加一句"这段讲什么"作为前缀。chunk #8 会被前置 `[本段位于第2章 2-1 节，讲标准化经济性背景，并提到改正工業標準化法施行时间和 JNLA 制度]` 再 embed，让向量捕捉子主题 | 1 周 | 经 Anthropic 报告失败率降 35-49% |

本次作品集**不实施这些**——它们是合格的"已知问题 + 下一步"，而**会讲清楚问题在哪、为什么、怎么修**，这比真的去修了更能体现工程深度。
