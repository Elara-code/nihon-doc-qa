## 优化一：混合检索（Hybrid Search）

### 问题
纯向量检索在**日文型号 / 编号 / 表名**上不可靠。例如问"入库登记功能的编号"
（期望 `INV-002`），向量会因为 `INV-001 / INV-002 / INV-003` 语义几乎相同而召回错号；
"T_STOCK"这类表名同理——它们需要的是**精确字面匹配**，恰恰是向量的弱项。

### 方案
- 加 **BM25 关键词检索**（`rank_bm25`），与向量检索并行召回。
- 中日文没有空格分词，且没用 MeCab/jieba，自写 `src/tokenizer.py`：
  ASCII 型号整词保留（`inv-002`）+ CJK **bigram**，让 BM25 能处理中日混排。
- 两路结果用 **RRF（Reciprocal Rank Fusion）** 融合：
  `score = Σ 1/(k + rank)`。只看排名不看原始分，天然规避
  "向量距离"和"BM25 分"量纲不可比的问题。

### 效果
> 回填：在型号/表名类问题（如 Q4）上，纯向量命中率 约X% → 混合检索 约Y%。
> 截图 `docs/retrieval-comparison.md` 里 Q4 这一行的 vector vs hybrid 对比。

## 优化二：重排序（Rerank）

### 问题
混合检索召回的 top-k 里，相关度排序仍不总准——尤其是
**聚合型问题**（如"数据库一共几张表"，Q9）和需要精确语义判断的问题，
最相关的整段不一定排在第一。

### 方案
- 加 **交叉编码器** `bge-reranker-v2-m3`：把 query 和每个候选拼起来联合编码打分，
  比双塔向量"分别编码再算相似度"精确得多。
- 代价是慢，所以只对**融合后的少量候选**（candidate_k=20）精排，取 top_k。

### 效果
> 回填：加 rerank 前后，Q9 等问题最相关段是否稳定排到第一；整体命中率 约Y% → 约Z%。

## 怎么把效果讲得有说服力

⚠️ 提醒：当前 `samples/sample_spec.txt` 很短，几乎都在一个 chunk 里，
三种模式可能都接近满分——**对比不出差异**。要让优化效果可见，二选一：

1. **加大文档**：放一份几十页的真实（脱敏）日文规格书，chunk 数上来后差异才显现。
2. **加干扰项**：在测试集里多放型号/表名/聚合类的难题，让纯向量更容易失分。

跑 `python scripts/compare_retrieval.py`，把 `docs/retrieval-comparison.md`
里三种模式的命中率表截图，就是最直接的素材。
